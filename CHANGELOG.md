# Changelog

All notable changes to Kami are documented here. The project is currently in the Unreleased milestone.

## Unreleased

### Editor typography

- Raised the editor chrome off the 11px floor onto one deliberate type scale, declared once as `--type-*`, `--leading-*`, and `--control-*` custom properties in `styles.css` instead of being repeated as pixel literals in three stylesheets. The ladder is 12 / 13 / 14 / 15 / 16 / 18 / 22 / 28.
- Body text and form controls now sit at 13-14px, secondary text at 13px, and metadata, counters, badges, and status words at 12px, so nothing in the editor chrome is set below 12px. Headings get three clear steps above the body rather than three shades of the same size: card titles at 16px, section and panel titles at 18px, and stage and page titles at 22px.
- Applied the scale across the Guided shell, the Full Editor, the right rail, the stage panels, the Inspector and its drawer, the device picker, the translation matrix, the bulk action bar, the connected-canvas captions, and the canvas status bar.
- Gave the larger type room to sit in: line heights, button heights, form control heights, card padding, and rail and list row heights all grew, and the two editor columns, the Flowboard rail, and the top bars were widened or heightened to match.
- The exported slide design is unchanged. The artboard rules on `.slide-canvas`, `.device-status-bar`, and `.template-preview` still size type against the 1242 x 2688 export, because the readability problem is the editor around the artboard, not the artwork inside it.
- Removed the shell-scoped size override that existed only to lift the shared Inspector and canvas meta text above the old floor: those classes now read the same scale as the rest of the shell, so a size is declared in one place. The rail's type floor is now 12px.
- Contrast, focus states, responsive behaviour, and `prefers-reduced-motion` support are unchanged; no colour value and no focus or motion rule was touched.

### Guided mode

- Added Guided mode, a four-step path through work the editor already did: Add your screenshots, Choose a look, Write your words, Download. Each step has one primary action in a sticky footer alongside Back and Skip, a step progress indicator, and plain wording for screenshots, slides, phone style, show the whole screenshot or fill the frame, and download.
- Guided mode is a UI-only browser preference. A stored choice always wins; otherwise it opens as the default only for a genuinely first-time visitor, with no restored project and onboarding still outstanding, so a returning author keeps the Full Editor.
- The complex control set is moved, not removed: a More options disclosure renders the existing Flowboard stage in place, and Refine is reachable as an advanced link from Choose a look and Write your words. The stage panels come from the same hook the Full Editor uses, so there is no second renderer and no second import, export, autosave, or project path.
- Added an explicit Guided / Full editor switch to both shells, a way back to guided from the Full Editor's rail, and an "Open full editor" path out of every guided step. Undo/redo, save/open, preflight, the export gate, connected canvas mode, and the translation matrix stay in the Full Editor.
- Fixed the blocked export message: the reason is now shown as visible text in a status line that the Export button also points at, instead of living only in a title attribute on a disabled control.

### Flowboard layout and usability

- Reorganised the Full Editor into one full-width main area and a single right rail. The persistent left stage rail is gone: stage navigation moved into the rail as a compact vertical Steps list, so a stage, its state, the deck facts, and the common actions are read in one place instead of being split across two columns.
- The rail now carries the Steps list, the active stage's reason, the deck at a glance with a setup count, the up-next jump, the draft and export notices, the editor guide, the classic-editor escape hatch, and the Guided / Full editor switch. The step state is printed once, on the entry that owns it: the top bar is the project surface only, the stage header names the stage and its position, and the footer bar is a position rather than a second status.
- The rail follows the viewport: a permanent right column on a desktop, a dismissible bottom sheet with a visible Steps toggle on a tablet, and a dismissible side sheet on a phone, where a compact stage selector above the content keeps the current stage in view without opening anything. The main area is full width at every size and no new left navigation was added.
- Stage navigation keeps its keyboard behaviour: roving focus with the arrow keys and Home/End in both the rail list and the compact selector, `[` and `]` to step between stages from the main area, Escape and the scrim to close the sheet, focus moved into the sheet on open and returned to the toggle on close, and the sheet inert while it is closed.
- Split the slide card state into three structural states: the slide being edited, the slides in the bulk selection, and everything else. The edited card carries an Editing pill, a pencil corner mark, a solid ring, `aria-current`, and a state sentence in its label, while a range selection keeps a dashed ring, a tick mark, and a Selected pill, so the two can no longer be told apart by a background tint alone.
- Added an always-visible legend in the Frame and Story stages that explains both states before a second card is chosen, and renamed the single-slide panel headings to say which slide is being edited.
- Made the Refine inspector drawer reachable: the panel is now a bounded flex column with the Inspector's own scroll region doing the scrolling, so the bottom of the panel is no longer clipped, and the drawer gained a header with a close button.
- Bounded the shell body row so the rail can no longer grow past the shell and hide its own lower half, at desktop and tablet sizes alike.
- Replaced the content-count `auto-fit` stage grid with an explicit per-stage template, so a stage with a single side panel no longer reserves an empty second track. The Frame selected-capture panel and the Ship export panel now span the row, and the Intake and Refine stages keep their two real columns. Stages collapse to one column at 1023px and below.
- Unified Export enablement behind one gate shared by the top bar and the Ship stage, so a blocked or running export can no longer be shown as available in one place and blocked in the other. Blocking checks keep their slide numbers in the message, warnings stay non-blocking, and a running export reports its progress.
- Relaxed the Flowboard host constraints so the shell is no longer clipped on short or mobile viewports: the app shell keeps the viewport height instead of a 680px floor, very short windows fall back to page scrolling, and the wrapping mobile top bar grows with its content.
- Made the tablet rail sheet dismissible with a scrim, Escape, and a visible close button, with focus moved into the sheet on open and returned to the toggle on close. The panel is inert while the sheet is closed, and the existing dialog Escape handlers are untouched because the dialogs live outside the shell.
- Raised the shell type floor to 11px, replaced the failing greys with contrast tokens that clear 4.5:1 on every shell background, added a shell-scoped floor for the shared Inspector and canvas meta text, gave cards and rail entries an explicit focus ring, and honoured `prefers-reduced-motion`.

### Flowboard story stage

- Added a translation matrix to the Story stage with one row per beat and one column per supported locale, so a deck's localized copy can be read across every language at once.
- Each cell reports the headline and supporting copy it holds, marks a missing translation instead of quietly showing the English fallback, and offers inline editing or a hand-off to the normal copy editor in the Refine stage.
- Inline cell edits go through the same update path as the Inspector, so one burst of typing is one undo step, autosaves like any other edit, and lands in the project document as an ordinary locale message.
- Added a completion summary in the form `4/6 slides · 8/18 fields translated`, counting headline and supporting copy per beat and locale and leaving fields the deck never used out of the total.
- Kept the matrix in table semantics with per-cell text for screen readers, arrow-key cell navigation, Escape to close an open cell, and right-to-left badges plus `dir` on right-to-left copy.
- The column header still sets the active preview locale, and the beat strip keeps multi-select, add, duplicate, delete, move, and apply-style-to-all.

### Device frame

- Replaced the three hard-coded device frames with a parametric catalog: every preset is now data describing a display resolution, a body built from a bezel and corner radii, a cutout, an orientation, a palette, and the safe area the operating system reserves. Frames are drawn from those numbers with CSS and computed SVG paths, so there is no bundled device image, no traced manufacturer outline, and no logo.
- Added twelve presets grouped by family: iPhone, iPhone SE, iPhone (island), iPhone (island max), iPad mini, iPad Air, Android, Pixel, Galaxy, Android tablet, No frame, and a landscape Canvas for feature graphics. Handset ratios are labelled the way a display spec is written, and each option shows its ratio and resolution.
- Replaced the Inspector's device dropdown with a grouped picker that draws each frame from the same catalog geometry the slide uses, so a button and an exported slide cannot disagree. Guided mode offers a shortlist of the common frames and keeps the rest of the catalog one disclosure away.
- Applied the selected geometry in the shared slide renderer, so the preview, the connected strip, and the export draw the same body, bezel, radii, and cutout. A notch, pill, or camera hole is one computed path in display coordinates, and the capture keeps clear of it.
- Kept `iphone`, `android`, and `none` working, and made older spellings such as `iphone-x` and `feature-graphic` open on the preset they meant. A saved project only ever carries a current ID, the document version is unchanged, and a value the catalog does not know falls back to the default.
- Added an optional mobile status bar to the device frame with a fixed 9:41 clock plus cellular, Wi-Fi, and battery indicators drawn from local CSS and SVG shapes.
- Added a per-slide `showDeviceStatusBar` setting with an Inspector toggle, defaulting to on for iPhone and Android presets and off for frameless output.
- Positioned the status chrome in the device safe area inside the shared slide renderer so previews and exports match, with local shapes, no system-clock dependency, and no pointer capture that would block dragging the screenshot layer.
- Fixed imported captures rendering cropped: the screenshot now sits in its own aperture box that honours a per-slide `screenshotFit` policy of `contain` or `cover`, and `contain` is the default so a new import is never cropped without the author choosing it.
- Added an Inspector control for the screenshot fit, with a hint describing the current choice and the named capture.
- Inset the capture below the reserved status bar band and off the rounded frame edge while the chrome is visible, and revealed a neutral backdrop for the letterbox of a contained capture, dark for framed presets and light for frameless output.
- Moved the aperture into a shared `DeviceAperture` renderer used by both the editor canvas and the export stage, and added a fallback to the import prompt when a stored capture cannot be decoded.
- Persisted `screenshotFit` per slide; projects saved before the field existed restore as `contain` and documents with an unsupported value are rejected by project validation.

### Canvas editing, drop assignment, and device variants

- Gave the Refine canvas the editing primitives a screenshot tool is expected to have: toggleable safe-area, centre, and thirds guides that take no pointer and are excluded from export; keyboard nudge of the selected layer at 1%, 10% with Shift, and 0.1% with Alt; align, distribute, bring-forward, and send-backward each committed as one undo step; and an optional bottom-to-top `LayerId[]` ordering applied as a `z-index` rather than by moving DOM nodes, so stacking became a property of a slide instead of a rule in the stylesheet.
- All of it resolves through one module of pure geometry that measures nothing and knows nothing about React, so the guides, the nudge, the arrange bar, the Refine tray, and the Inspector share a single answer rather than three that can drift, and the transform controls are one component rendered by two surfaces so they cannot report different numbers for the same layer. A nudge and a drag both land in canvas percentages, which is the unit a transform is already stored in; the delta is clamped only when the layer's box has been measured, so a missing measurement degrades to a plain nudge instead of swallowing the key; and the horizontal arrows mirror under `dir="rtl"`.
- A stored layer order is never trusted wholesale: unknown ids are dropped, repeats collapsed, and anything missing appended in catalog order, so a hand-edited or partial list still yields every layer exactly once without depending on a caller having handled a newly added layer. A slide whose order resolves back to the default writes no field at all, and a slide with no field resolves to catalog order, so an older project is untouched and an unedited deck still serializes byte-identically.
- Added drag-and-drop screenshot assignment on Frame stage cards, Intake deck thumbnails, and the device aperture placeholder, with surplus images appended as new slides, so a capture can be moved onto a slide by drag as well as by picker. One drop is one undo step, a dropped file that is not an accepted capture is reported rather than swallowed, and the decision is a pure plan rather than an effect, so the three drop targets cannot disagree about what a drop means. A capture dragged between cards carries a Kami-only data transfer type, because a capture is not a file and the browser would hand over a `File` for a text selection just as readily.
- Added a per-slide background fill — `theme`, `solid`, `gradient`, `image`, or `panoramic` — as one optional record rather than a set of switches, so "the image layer is on" and "the fill is a gradient" cannot contradict each other: the kind alone decides whether the existing background-image layer *is* the fill. The renderer applies the result as CSS custom properties, so the editor preview, the connected strip, and the export stage cannot diverge, and an image fill keeps the theme paint underneath so a missing or failed image degrades to the theme rather than to a hole. The focal point is normalized 0..1 because one slide exports at six profile sizes and a pixel focal point drifts on every one of them, and it is physical rather than logical so the Arabic export frames the artwork the same way the English one does.
- Fixed a restore path that silently discarded `image/svg+xml` backgrounds, which the path validator, the JSON Schema, and the demo project all permit: the document validated on open and then lost the artwork.
- Added per-device export variants. `outputVariants` gains per-slide `deviceOverrides` instead of duplicating slides, and a slide absent from `deviceOverrides` uses its own fields, which is the one rule that makes the whole feature additive and the reason no migration exists. A variant is a reference set and never a copy: duplicating slides per device would inflate `slides`, break the synthetic `scene.width`, and desynchronise every consumer that reads a 1-based slide position — preflight slide numbers, the ZIP numbering, and the "open this slide" affordance — so a variant's render is numbered by its position in the authoring deck. Copy, theme, layout, and the fill are deliberately not overridable per device, because a reader looking for the words on a slide should find them in one place.
- `serializeProject` no longer overwrites `outputVariants` with a hard-coded record, and the profile the editor opens on is decided in one order: `selected === true` on a profile is the authority, and only if no profile claims it does the reader fall back to the first enabled variant in array order. Export filenames are minted in one place as `<profile-id>--<variant>--slide-NN.png`, because two device variants would otherwise both want `slide-01.png` and a bundle that overwrites itself is worse than a long one; the profile *id* is used rather than its display name so renaming a profile in the catalog cannot change what a bundle written last month is called.
- A variant with a missing capture now blocks that variant's export rather than emitting a placeholder, because a placeholder PNG reaches a store review as a rejection and is indistinguishable from a finished slide once it is in the bundle. A profile reports `ready` only when every *enabled variant* targeting it is complete, where the previous `slides.every(s => s.screenshot)` over the base deck called a profile ready while a variant quietly exported a placeholder.
- Collapsed the two copies of `isSafeAssetPath` into one exported function that both the validator and the restore path import, because they had diverged and neither was the truth: a document pointing at `../../foo.png` was refused by the check that runs first and then accepted by the restore that runs after it. The control-character and `..`-segment tests now run before either allowlist branch can return true, because the branches used to come first and short-circuit, so `https://example.com/../secret.png` and a `data:` URL carrying a newline were both accepted by a rule that promised they were not. The known limits are written next to the code — C1 controls and U+2028/U+2029 are not refused, `C:\hero.png` is refused as a scheme, and the data-URL rule checks the mime prefix only — because a limit nobody can read is a limit nobody can keep.
- The project document version stays 1 throughout: every new field is additive and optional, and an untouched deck still serializes byte-identically. The cost is documented rather than hidden, in a warning in `docs/project-file.md` that an older build re-saving a document carrying variants will flatten them, because `serializeProject` is a full rewrite and nothing rejects the result.

### Export manifest, merged variant preview, and store listing

- Added an export manifest in the Ship stage: one row per file the export will write, carrying the store profile, the device variant, the deck position, the slide, the output name, the pixel size, and the locale the PNG is drawn in. It is derived from the export plan rather than persisted, so there is no field to migrate, no version to move, and no way for a manifest to disagree with the plan the export is built from — a manifest is a question asked of the plan, and it is asked before a single pixel exists.
- The manifest has to reconcile *exactly* against the archive that comes back: same count, same names, same order. A reordered bundle is reported as `outOfOrder` rather than folded into `missing`, because every file is present and only the sequence is wrong, and reporting a present file as absent is the kind of false alarm that teaches an author to ignore the check.
- Added a merged per-variant preview to the Refine canvas: a variant selector that renders the resolved slide for one slide at a time, through the same `resolveDeviceOverride` the export iterates, with the deck itself offered as the first option so returning to editing is a selection the author makes rather than a mode they have to discover. Asking a variant to draw a slide it does not render resolves to its own first render and says which slide was asked for, because quietly falling back to the deck would show a device the author did not choose.
- The read-only claim is structural rather than conventional: `exportRenderProps()` is the only way either non-editing surface builds its props, and it returns `exportMode` typed as the literal `true` so a call site cannot opt back into the write path and believe it has not. The returned object has no key through which a transform, a selection, a nudge, or a drop could be written, so there is nothing to forget to disable. Fitting the export width into the stage scales a wrapper rather than rendering a second canvas, so the DOM inside is the export stage's own markup, and a test asserts the two canvas subtrees are byte-identical using a scanner that throws rather than returning empty.
- Added a store listing preview that describes how a set reads in a carousel — how many images sit side by side at the front, where the icon tile sits, whether a headline will wrap on this tile's shape — and then reports what this particular set actually contains. The copy lives beside `exportProfiles` as data and is phrased descriptively, because the editor cannot open a store and copy that claimed to know would be wrong the first time a store changed; a test rejects the words `must`, `requires`, `only allows`, and `reject` in it, and `headlineReference` is a reading length rather than a limit, so nothing is ruled. Headlines are measured in the locale the export will really draw them in, because measuring the English copy beside a Spanish tile reports the length of something nobody sees.
- The store preview renders the cheap thumbnail rather than a full renderer per slide, since the off-screen export root is already laid out one slide at a time, and it carries no controls at all, so there is nothing to keyboard-navigate or label.
- No new persisted field. The schema, the migration, the validators, the templates, the demo project, and the document version are untouched.

### Export correctness

- Fixed a new slide joining no variant. `OutputVariant.slideIds` is a reference set, which is the right design, but nothing maintained it: creating a variant snapshotted the deck's ids, adding a slide afterwards updated `slides` and nothing else, and `planExportEntries` — which faithfully renders what the variants name — then omitted the new slide from every export. Measured on a ten-slide deck with three variants: three manifest rows instead of thirty, every variant still summarising itself as "1 slide", no warning, and a manifest that looked complete because it only listed the three files it planned to write.
- `reconcileVariantSlideIds` brings every variant back in step with the deck, and it is called from `commitEditorUpdate`, the one function every deck edit funnels through. Patching each call site that changes `slides` is how the bug arrived: `addSlide` updated `slides` and nothing else. The rule is that a variant covers the whole deck, which covers both halves of the fault: a slide the deck gained is added, and an id the deck no longer has is dropped, because a dangling id is a reference to something absent and the document validator rejects it, so a deleted slide would otherwise turn a valid project into an invalid one. Full coverage rather than opt-in because no control anywhere narrows a variant to a subset, so a subset is not authorable. It runs only when the slide list actually changed and returns the same array reference when nothing moved, which is what keeps an unedited deck byte-identical and stops a keystroke in a name field rewriting every variant.
- The draft-restore path needed its own call, because it is the one ingress that is not an edit: `replaceEditor` installs the restored state directly, bypassing the funnel, and it is precisely where a stale reference *arrives* — a document written before the fix, and `restoreOutputVariants` filters to existing slides rather than adding missing ones, so nothing downstream repaired it either. The tell was an inconsistency rather than a crash: `openProjectFile` already reconciled, so the same document behaved two different ways depending on which door it came in. Measured, a three-slide deck with two variants naming one slide each planning 2 PNGs instead of 6, beside "Nothing blocks the export" in the Ship review, because a plan that renders what the variants name is faithful about a plan that renders the wrong slides. It is the same call and not a second rule, so a current draft is installed — and autosaved — untouched.
- Fixed an empty export plan never being explained. `blocked` is computed by `findIncompleteVariant`, which iterates the same `enabledVariantsForProfile` filter, so no variants means no incomplete variant means `blocked: null`: the refusal channel and the emptiness channel were one channel, which made `blocked` structurally incapable of saying "this deck exports nothing". Every route to an empty plan — a store target nothing aims at, every variant for it turned off, a `slideIds` that is not an array, one that is empty, one that names no slide the deck has, or no slides at all — was read the same reassuring way: a green tick on the review row, a manifest that was merely absent, "0 PNGs" in the Files record, a clean preflight, an enabled Export button, and a run that finished with "downloaded with 0 PNGs". A deck whose variants all target the App Store, switched to Google Play, passed every preflight check because there is nothing wrong with the deck, and then planned zero files, with preflight and the plan free to disagree because neither was watching the other.
- `ExportPlan` now carries a second refusal field, `unassigned`, set whenever `entries` is empty and derived from the *result* rather than re-derived from the inputs, so a route to emptiness nobody has enumerated is still reported. It names one of four reasons — no slides, no variant targeting the store target, every variant for it turned off, or an enabled variant naming no slide the deck has — and reaches the author through the surfaces that already read refusals, so the top bar, the guided Download step, and the Ship stage all disable from one value with no per-surface logic. It is a return value and not an assert or a throw, because `blocked` names a variant, `unassigned` names a store target, and this codebase returns refusals as data. The gate carries `slideNumbers: []` for it deliberately: none of the four reasons is about a particular slide, so there is nothing for an "open this slide" control to point at and a fabricated number would be a worse lie than none.
- Removed the `revision` block `serializeProject` wrote and never read: `{ number: 1, createdAt: new Date(), message: 'Saved from Kami editor' }` was a hardcoded number, a fresh clock, and a constant, and `EditorProject` has no `revision` field, so the value was destroyed on load and re-fabricated on save. On a document whose whole pitch is that it lives in Git next to your code, opening the app and saving with no edits produced a two-line diff every time, so a real change could not be told from a no-op save. It was already costing the suite workarounds — two persistence tests blanked `createdAt` before comparing, and the gate deleted the block before diffing. The schema keeps `$defs.revision` so the vocabulary is not lost, but if it is ever reintroduced it should be derived from the content, never from a clock.
- Stopped the off-screen export stage mounting every entry of every variant permanently. On a nineteen-slide deck with three variants, 2,736 of the document's 4,249 elements were that one hidden container, and ten keystrokes into a variant name cost 905ms — about 90ms per keystroke for typing into a text field. It now holds only the measured variant's entries while idle, which is measurement-identical rather than merely plausible: `collectExportPreflightBounds` takes `slideNodes.slice(0, N)` and pairs them with `measuredSlideIds` by position, and the plan is variant-major, so the first N mounted nodes are the measured variant's slides whichever entries are mounted. When an export is actually running it waits for the full stage to mount and throws with a loud count if it is short, rather than handing the rasteriser whatever happened to be there and shipping a bundle missing two of three languages.

### Editor entry, variant language, and manifest navigation

- Choosing a deck now opens the editor. Applying a template, loading the demo, and starting a blank slide all left the author on Intake — a checklist and a dropzone — rather than on the slide they had just built; each now lands on Refine, the stage that holds the canvas and the inspector.
- The deck-creating handlers are joined to that stage by a count, `editorEntryRequest`, rather than by a boolean. `activeStage` is local state inside the Flowboard shell while every action that creates a deck lives one level above it, and the template picker renders in App as well, so wrapping the handlers would have missed the template path entirely; a count is the one signal that crosses that boundary without either side owning the other's state. A count rather than a boolean because a deck can be replaced several times in one session — a template, then the demo, then a blank slide — and a boolean would fire only for the first, leaving the author on Intake staring at a deck they cannot see with nothing on screen to say why. Zero means "none yet", so the effect does not fire on mount and throw every restored project into the canvas and past the Intake checklist that reports what is still missing, and an unrelated re-render does not yank the author back out of the stage they moved to. It is tested as behaviour and not as markup because the Refine stage's markup is identical whether or not the shell navigated to it, so a string assertion could not tell the two states apart at all.
- A variant can be put in a language. `locale` has been on `OutputVariant` since the field was introduced — persisted, validated, deciding what every PNG in that variant is drawn in, and recorded in the filename — but it had no editor control at all: a new variant inherited the deck's active locale and nothing could move it afterwards, so a deck could describe several devices but only ever one language. Right-to-left options are labelled as such in the list, because a language that lays out backwards should not be discovered in the export rather than in a picker.
- One field on one variant rather than a bulk "translate to" action. Copy is authored per locale in the Story matrix, and a variant pointing at a language whose copy is missing falls back to English per field, which is a real and inspectable state the author can see and fix; a bulk duplicate would instead fill the set with variants that silently export English twice, indistinguishable from a translated set until something downstream says otherwise. Nothing new is persisted: `locale` was already a field on the variant, and the editor-entry signal is session state, so the schema, the validators, and the document version are untouched.
- Every export manifest row can now open what it names. The Ship manifest is the only N x M view of a deck — one row per planned entry, carrying the file, the variant, the deck slide, the size, and the locale — and it was text with no link out of it, so an author reading 57 rows had no route from "this row" to "this variant and this slide, actually drawn"; each row now carries a control that opens the existing merged preview for exactly that variant and slide. The variant list's own "Show on canvas" control calls the same `onOpenVariantPreview` and lands through the same function in the stage hook, so there is one way into that surface rather than two that can disagree about where they end up, and the control is only rendered where the shell can actually send the author — a permanently disabled button teaches an author the feature is broken, which is worse than its absence.
- The preview's slide position had to leave RefineStage's private state for that to hold. While it lived there, a row asking for slide 7 would have been overruled by whatever the stepper last held, which is precisely the failure the row is meant to prevent: a control that always reported the first row's variant and slide renders exactly the right button and opens exactly the wrong preview. The stepper and every manifest row now write one value the shell owns, and a row's arguments are asserted rather than inferred, because a markup string cannot say which variant and slide a handler was called with.
- The control is a real button inside the row's existing `th scope="row"` rather than a click handler on the row, because a handler on `<tr>` is unreachable by keyboard and unnameable to a screen reader and 57 of them all have to be reachable; a sixth column would have been a data cell with no header of its own. Each carries an accessible name saying which variant and which deck slide, since "Preview" 57 times over is not a name. The filename stays visible text, and the control says only that it previews: it opens the read-only merged canvas and exports nothing, so it claims nothing about writing a file.

### Test suite and gate

- The suite could not observe the editor. It ran in `environment: 'node'` with no jsdom, so no test ever mounted a component, no effect ran, and no handler fired: all twelve component test files were one-shot `renderToStaticMarkup` strings, and the two files a rewrite is most likely to change, `App.tsx` and `SlideCanvas.tsx`, had no coverage at all. The suite could report 744 green while the editor was broken the moment you touched it.
- Added jsdom, opted into per file with a `@vitest-environment` docblock so only the tests that need a DOM pay for the environment. Running it globally was rejected for two reasons: it cost roughly 520 seconds of setup for the static half and gained nothing, and it broke the stylesheet tests outright, because under jsdom `import.meta.url` is an http URL and `new URL('./x.css', import.meta.url)` throws. The include glob now covers `.tsx` as well, since the previous `.ts`-only pattern meant a JSX test could not even be named, and `SlideCanvas.drag.test.tsx` is the first test file that operates the editor: eight cases over the composition drag, covering proportional commit, the movement threshold, a second pointer, a non-primary button, a press on a control, an unmeasured canvas, and `exportMode` refusing a write even when a write handler is passed.
- Replaced the 13 assertions that read a stylesheet as text and regexed it with parsing done by a real CSS parser, so a test now asks whether a selector declares a property rather than whether the file contains a particular string. They asserted on formatting, and a CRLF checkout with no `.gitattributes` failed three of them on line endings alone. Converting them surfaced a false positive that had been passing: the pattern `selector {[\s\S]*?var(--flow-focus` was not scoped to the rule, so an unrelated focus rule *earlier* in the file satisfied it and the assertion would have kept passing after the drop target stopped using the token.
- Added `.gitattributes`, pinning text to LF in every checkout with `text=auto eol=lf` and marking the lockfile and binary assets as not-text. This is not cosmetic: the suite asserts on the text of stylesheets and on serialized project JSON, so `core.autocrlf=true` on Windows was enough to change test outcomes with no code changed.
- Added `npm run gate`, a deterministic judge that runs `tsc -b`, the tests, a test-integrity manifest, the schema/template/demo validators, and a byte-identity round trip, and exits with a code. The manifest is the anti-Goodhart clause: a removed or renamed baseline test is a gate failure in its own right, independent of whether the suite is green, and a rename shows up as one removal plus one addition so renaming cannot quietly delete coverage either. It is verified by renaming a test — the suite still passed and the count still read 752, and only the integrity check caught it. Test identity is recorded as a repo-relative POSIX path rather than vitest's absolute path, because recording the absolute one would have made the baseline comparable only on the machine that produced it. The script states its own limit in its own output: it answers "did the rewrite break what worked", which is decidable, and not "is the new editor better", which is not.
- Brought `scripts/` into the typecheck, which was in no tsconfig, so vitest never imported it and esbuild bundled it without typechecking. That revealed eight type errors in the gate's own round-trip check, including a `ProjectFile` import from `src/types` that never existed. The load-bearing ones were silent rather than loud: the check read `.ok` from a `ValidationReport` that has `valid` and then cast the report to reach `.issues`, so `validity === false` could never have been true; and it hand-rolled template slides from `slide.name`, `slide.layoutId`, and `slide.themeId`, none of which exist on `ProjectTemplateSlide` whose fields are `title`, `layout`, and `theme`, nesting the deck under a `project` key `EditorProject` does not have. Every wrong field was spread into the slide and ignored, so the six template checks were reconciling a deck that was really the tracked project's slides wearing new ids — they passed, and they were not testing the templates. The check now calls the app's own `createSlidesFromProjectTemplate`, and a `never`-returning helper carries its type annotation on the variable, since TypeScript only treats a call as a control-flow terminator when the callee is an identifier with an explicit `never` return type.
- The round-trip comparison is now full-byte rather than full-byte-except-one-block, which is the same edit that removed `revision`; the carve-out that deleted the field before diffing had been proving all but one line of a canonical document was a fixed point and quietly letting the one volatile line through, and it invited the next volatile field to be exempted the same way. The invariant it checks is `serialize(parse(serialize(p))) === serialize(p)` across the tracked project, all six templates, and the demo project, not "the checked-in file equals the serializer output": `screenshot-studio.json` is hand-authored and omits every optional field, so the serializer legitimately expands it, and what must hold is that opening a project and saving it again is a fixed point, which is the property a rewrite endangers and which a field added to the restore path but not the serializer shows up in as a byte diff rather than as a passing test.
